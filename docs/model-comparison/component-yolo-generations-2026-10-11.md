# Tokito component YOLO: full three-generation audit

Audit date: 2026-10-11. Scope: per-component detection/segmentation experiments. Board-family classifiers/detectors are separate models and are not counted as component generations.

Download the [generation summary CSV](component-yolo-generations-2026-10-11.csv) or the [full long-form metric and per-class audit CSV](component-yolo-full-metrics-2026-10-11.csv).

### G1 full recorded metrics

The seed-42 split is image-disjoint (33/9/11). Validation candidate-box metrics: precision 0.5871, recall 0.1786, mAP50 0.1761, mAP50–95 0.0681. Held-out test candidate-box metrics: precision 0.2835, recall 0.1401, mAP50 0.1356, mAP50–95 0.0419. Per-class test mAP50–95: IC 0.0824, capacitor 0.0432, connector 0.0000. The 2,384 labels are generated by connected components in PCB-Vision semantic masks, not manually reviewed object instances; they may merge touching parts, fragment one part, and omit other visible categories. So the held-out split is useful as a reproducible proposal-label diagnostic, not an estimate of real component accuracy.

### G3 full recorded metrics

The 70 unique records comprise the same 53 PCB-Vision images used in G1 plus 17 Tokito images (14 train / 3 validation). Public split is 33 / 9 / 11. The 415 local reviewed masks are in train and validation; no local test split exists. Seventy newly discovered iQOO gallery images were excluded because they lacked verified instance masks. Total manifest label counts (including external connected-region proposals) are 2,637: IC package 1,294; chip passive 601; connector 648; RF module 8; switch 35; discrete semiconductor 38; crystal 11; inductor 2. The external component-generation candidate manifest has 2,384 regions at its original resolution; the V2 training builder recomputes connected regions after resizing/letterboxing to 512 pixels and records 2,222 external instances, a difference of 162 regions. The model’s eight classes are package categories, not exact manufacturer/SKU, refdes, pins, nets or BOM/Gerber identities.

## Provenance and audit exceptions

- Parameter totals were counted directly from each `.pt` model’s learned parameters with Ultralytics 8.4.175. File byte sizes and SHA-256 hashes above identify the exact repository artifacts.
- G1 provenance: `data/external/PCBVision/component-yolo-experiment/training-report.json`, `data/external/PCBVision/component-yolo-experiment/results.csv`, `docs/PCB_VISION_BOX_CANDIDATES.md`, and `data/external/PCBVision/box-candidate-manifest.json`.
- G2 provenance: `models/partial-component-diagnostic/REPORT.md`, `training-manifest.json`, and `threshold-sweep.json`.
- G3 provenance: `models/component-segmentation-v2/REPORT.json`, `work/component-segmentation-v2/manifest.json`, and the train/val/test index JSON files.
- One ESP-12E still is annotated as `complete_visible_instances`, but it is in training and its annotation explicitly has `evaluation_valid=false`; it cannot be repurposed as a held-out score. The ESP32 frame review is partial and also in training.
- A later V2 run report records external P/R .762/.316 and local P/R 1.000/.185, but its checkpoint hash (`6e6ea32c41c469b2acbfb5abe6da60bd00c24146842698748328577ebd43ce29`) does not match the current repository V2 checkpoint. It is excluded from the graph until the matching weights and evaluation provenance are reconciled.
- G1 and G3 share all 53 PCB-Vision source images. G3’s external evaluation and label generation reuse the same family of semantic masks/candidate proposals, so those numbers cannot establish improvement over G1.
- These artifacts do not validate AR pose, camera calibration, 3D alignment, pin-level identity or exact component part numbers. AR alignment is a separate workstream.

## Bottom-line audit finding

G3 is the strongest available **candidate artifact** by the recorded external partial-region precision/recall, and it has segmentation masks, but the score is not a valid production accuracy claim. The very low Tokito partial recall (.136) and connector recall (.041 externally) show substantial misses. The current evidence does not support calling any of the three models production-ready. A real full audit requires exhaustive component masks on new, independent board specimens/capture sessions, group-separated train/validation/test splits, and evaluation with one fixed instance-level protocol. Until then, use the graph as a transparent experiment history, not a leaderboard.
